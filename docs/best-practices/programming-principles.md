# Programming Principles

Use this as review criteria for every implementation.

1. Descriptive names.
2. Sparse comments that explain why.
3. DRY, but not premature abstraction.
4. Unit tests for pure logic.
5. Integration tests for workflows.
6. Consistent style via formatter.
7. Explicit error handling.
8. Public documentation for public APIs.
9. Measured performance work.
10. Input validation and security boundaries.
11. Version control and change records.
12. Planning before implementation.
13. Appropriate data structures.
14. Modular cohesive code.
15. Edge and error scenarios tested.
16. Minimal global mutable state.
17. Single responsibility.
18. Time and space efficiency.
19. Refactor while green.
20. Record lessons from failures.
